# Academic learning practice isolation

Choosing the example opens the real Nodus workspace with a private application profile. The original window is hidden, and its active vault, unsent drafts, conversations and ongoing work stay in the original process. The practice is not registered in the user's vault list. Its header identifies it as isolated practice and provides a return action.

The private profile owns its vault database, Global Library catalog and files, indexes, ideas, relationships, conversations, saved artifacts and queues. Even changing the recovery-folder setting inside practice cannot redirect its Library to personal storage. The example import endpoint refuses to run in an ordinary profile. Initial settings copy only model roles and presentation; no corpus, registry, histories, integration configuration or personal storage paths are copied. Existing encrypted provider records can be reused in the private profile; plaintext legacy records are not copied.

Returning to work closes the practice window and restores the original window without switching its vault. Closing the practice window does the same. Practice files and lesson checkpoints are retained so that another lesson can continue with the same source and results. Tutorials exposes an isolated-practice action for each lesson. A new practice starts with source preparation before advanced lessons. Only validated learning progress is merged back into the user's progress; practice entity identifiers and settings never become references in the original vault.

“Delete practice and return” confirms deletion, waits for the private process to exit, and removes that fixed private directory. It preserves the original stores and the user's learning progress. It never finds or deletes documents by title, filename, quotation or similarity. Exiting the original app also stops the private process; losing the parent IPC connection closes practice.

The wizard dims and restricts unrelated controls only during actionable checkpoints. Preparation, extraction, streaming replies, report generation and evidence loading remain visible without the wizard shade or click restrictions. Ordinary configuration and confirmation dialogs retain their normal modal backdrop.

Verification uses local deterministic providers and two real Electron processes: prepare a private source, send a cited answer, open evidence, return to an unchanged personal corpus, continue extraction and graph lessons, and delete the private files. It also checks private Library routing after an attempted folder change, hidden vault discovery, learning-progress retention, original model/sidebar preferences, and all 12 interface languages in both themes. No real provider credentials or responses are needed for these tests.
