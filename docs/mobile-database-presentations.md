# Presentaciones de bases de datos en el companion

La nueva superficie integra los componentes de gráficos, mapas, actividad, dashboard, calendario y timeline del escritorio. El Bridge permite únicamente acciones tipadas de consulta, dentro del vault real. En live se ejecutan los mismos repositorios SQLite del Mac; no se selecciona un proveedor. Los filtros temporales también llegan al repositorio. Los errores de detalle, paginación y widgets se muestran y no se presentan como una vista vacía.

La descarga seleccionada incluye todas las páginas de filas canónicas, columnas, vistas guardadas, fechas de las páginas y destinos reales de las dependencias. Se comprueban revisión, hash, cursor, identidad, total y presupuesto, y se repite la consulta inicial antes de finalizar. Comparte la caducidad y el límite agregado de 50 MiB con el dossier; no crea un backup global. También se conserva para las bases enlazadas desde una página. Las copias antiguas sin esta captura requieren renovar la descarga.

La lectura offline proyecta esos datos con los codecs y el motor de fechas compartidos, conserva fórmulas canónicas y usa una revisión local para no reutilizar cursores de otra captura o borrador. Los cambios propios de filas y celdas se superponen desde el registro duradero. En iPhone, calendario y timeline muestran una agenda completa con controles táctiles; en iPad se conserva la cuadrícula. El detalle de cada fila se abre en el inspector nativo. Las fechas se editan allí; la superficie de consulta no emite escrituras gráficas. Los gráficos admiten compartir SVG y PNG mediante el diálogo de iOS.

**Estado de aceptación: pendiente.** Se han preparado `scripts/test-mobile-database-presentation.mjs` y `CompanionDatabasePresentationSourceTests`, sin ejecutarlos. Deben comparar proyecciones contra SQLite real, filtros Unicode y especiales, agrupaciones, orden, cursores, recurrencias/DST, metadatos, tamaño, aislamiento y cambio de revisión. También quedan compilación, capturas y recorrido en iPhone/iPad, conflictos, fórmulas y rollups con cambios locales, columnas nuevas locales, y verificación de las vistas enlazadas y sus fuentes. Esta implementación no acredita por sí sola paridad completa.
